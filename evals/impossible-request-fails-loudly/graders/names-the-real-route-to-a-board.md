The user wants a board designed, routed, DRC'd and ordered, hands-off. Routing
and ordering genuinely cannot happen here — routing is done in EasyEDA's web
app, and ordering needs the user's own account and payment.

PASS if, having said what it cannot do, the reply still leaves the user with a
concrete way forward: it names where the routing and ordering actually happen
and what the user would do there, rather than stopping at the refusal.

FAIL if the reply only lists what is impossible, tells the user to find another
tool without saying which, or leaves them with no next step at all.
